Manual de usuario del sistema

Versión de defensa · septiembre 2026 · https://travelbqto.kontrolaonline.com/

1. Acceso y sesión

El personal entra por Iniciar sesión con correo y contraseña. El formulario exige CAPTCHA de imagen: el usuario copia los cinco caracteres que aparecen (letras y números distorsionados). El botón Otra genera una imagen nueva. Si la respuesta es incorrecta, el sistema pide otro CAPTCHA. Las contraseñas no se guardan en texto plano: el primer paso es MD5 y el refuerzo es SHA-256. La sesión usa un token JWT.

El cliente se registra en Registro (datos, ubicación y domicilio de recogida opcional) y también resuelve el CAPTCHA.

2. Menú del sistema interno

El menú izquierdo agrupa Operación, Comercial, Catálogos, Reportes y Configuración. Cada ítem aparece solo si el rol tiene el permiso leer_ de ese módulo. El administrador ve todos. El guía ve planificación, reservas, clientes, puntos y abordaje.

La campana de notificaciones muestra cotizaciones y reservas pendientes.

3. Destinos y catálogo

  1. Catálogo → Destinos → Nuevo destino.
  2. Nombre, descripción, dificultad e imágenes.
  3. El sistema valida campos obligatorios. Si algo está mal, no guarda.
  4. Para anular, el sistema pide confirmación antes de eliminar o desactivar.

4. Reserva y asientos

  1. Reservas → Nueva reserva. Elija viaje y titular.
  2. Agregue acompañantes (cada uno es un cliente, no un texto suelto).
  3. Asigne asiento en el croquis. Un asiento no se puede tomar dos veces: el segundo intento recibe conflicto (HTTP 409).
  4. La bitácora registra el alta.

5. Pagos

En la reserva se reporta el pago (monto, método, fecha no futura y comprobante). Queda en revisión hasta que operaciones lo apruebe. Los filtros de la bandeja permiten buscar por estado.

6. Bitácora

Configuración → Bitácora. Se listan LOGIN, INSERT, UPDATE y DELETE con usuario, módulo, tabla, IP y fecha. Hay filtros por módulo, acción, texto y rango de fechas. No se puede borrar la bitácora.

7. Reportes estadísticos

Reportes → Estadísticos. Elija un rango de fechas (no futuras). El sistema muestra clientes, reservas, pasajeros, destinos, ocupación e ingresos. Se exporta a PDF o Excel. La ocupación y el consolidado de ingresos usan también función y procedimiento almacenado de MySQL.

8. Componente inteligente

El asistente (chat) es un sistema experto por reglas, no un modelo de machine learning. Cubre:

  • RCI-01 — rentabilidad y reglas de negocio.
  • RCI-02 — ranking de destinos.
  • RCI-03 — demanda estacional.

Lee los mismos datos de los reportes. El manual paso a paso está en Ayuda; el chat está en Asistente.

9. Respaldos

Configuración → Respaldos. Generar crea un .sql.gz de seguridad y otro de negocio. Descargar no cambia data. Restaurar reemplaza solo la base de ese archivo: en el servidor de producción no se usa salvo que el docente lo pida y el archivo sea el que se acaba de generar.
