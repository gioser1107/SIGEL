2. Demo de 8 minutos (ensáyala 3 veces en el dominio)

  1. Login + CAPTCHA. Falla una vez a propósito → “el CAPTCHA rechaza bots”. Luego entra. Di: “la clave no va en texto plano: MD5 y luego SHA-256”.
  2. Menú. Recorre Operación / Comercial / Catálogos / Reportes / Configuración. “Cada ítem aparece según permiso leer_ del rol”.
  3. Validación. Destino o cliente: pon un correo mal o números en el nombre. “Valida front y back; el API responde 422”.
  4. Reserva + asiento. Asigna un asiento. Segunda pestaña, mismo asiento: 409. “InnoDB, SELECT FOR UPDATE, índice único. Eso es concurrencia y recuperación” (SO 4%).
  5. Bitácora. Filtros. Se ve LOGIN e INSERT. “La escribe el sistema y también triggers. No se puede borrar: hay trigger BEFORE DELETE”.
  6. Campana. “Notificaciones: cotizaciones y reservas pendientes”.
  7. Reportes. Rango real → PDF o Excel. “Parametrizado, sin fechas futuras”.
  8. Asistente. “¿Qué destino rinde más?”. Di: “sistema experto por reglas, RCI-01/02/03, no es un modelo ML entrenado”.
  9. Respaldos. Generar y descargar. No restaurar backup viejo.

5. Docente de Proyecto (10%)

Casi todo es el documento: título, diagnóstico, instrumentos, propuesta, objetivos, justificación, procesos, marco teórico (1,0), marco legal, planificación, Cap. I–II, normas, redacción, equipo.

Técnico (1,5 juntos): bitácora 0,5 + MD5 y CAPTCHA 1,0.

El baremo pide cifrado MD5. El primer paso del hash es MD5, como el trayecto. SHA-256 va encima porque MD5 solo ya está roto. El usuario escribe 5 caracteres de una imagen CAPTCHA; el token va firmado (HMAC) y caduca en 5 minutos. No usamos reCAPTCHA de Google para poder demostrarlo offline.

Si pide ver el código: backend/modelos/usuario_modelo.py → hashear_md5. Login: imagen + campo.

7. Sistemas operativos (5%)

Apache o LiteSpeed de Fastcomet sirve https://travelbqto.kontrolaonline.com/. Ese dominio es el VirtualHost. El archivo sigel.conf muestra el proxy a Uvicorn :8000. La app Python habla con MySQL por .env / database.py. PHP no aplica: la cátedra pidió Python. Los errores se ven en HTTP 400, 409, 422, 503, no en php.ini.

Concurrencia 4%: dos pestañas, mismo asiento. Uno gana, el otro 409 “el cupo o asiento ya fue tomado”. Motor InnoDB, transacción, with_for_update(), índice único. Recuperación = no dejan dos reservas del mismo asiento; rollback si hay IntegrityError.

8. Preguntas trampa (respóndelas así, no de otra forma)

Si dicen…Tú dices…
¿Dónde está el PHP?La unidad de SO enseña LAMP; este proyecto se autorizó en Python. Equivalente: FastAPI = backend, Uvicorn+Apache = HTTP.
¿MD5 o bcrypt?MD5 como pide el trayecto, más SHA-256. No bcrypt, para que encuentren md5() en el código.
¿Es inteligencia artificial?Sistema experto por reglas. Analítica descriptiva. No predicción entrenada.
¿Dónde está el stored procedure?Diseñado; el hosting no permite CREATE ROUTINE (1370). Triggers sí. Consulta equivalente en phpMyAdmin.
¿Cómo evitan doble asiento?Lock de fila + índice único + 409.
¿El acompañante es texto?No. Es cliente en reserva_clientes (3FN).
¿Quién modificó este registro?Bitácora: usuario, tabla, registro, IP, fecha. Trigger + API.
¿El CAPTCHA es de Google?No. Imagen propia, 5 caracteres, token HMAC, caduca 5 min. Funciona sin internet de Google.
